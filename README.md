# Отказоустойчивость средствами Apache ZooKeeper (вариант 1: Программист, разработчик на 1С)

Практическая работа № 4 по дисциплине «Инженерия данных».

Выполнила: Андреева Наталия Леонидовна, группа J3310.

## Что сделано

Поднят ансамбль из трёх серверов ZooKeeper 3.9.6 в Docker, проверены роли серверов, потеря одного и двух серверов, возврат серверов и эфемерный узел. Координатор расчёта пар навыков из ДЗ № 3 (репозиторий hh-lake-1c) подключён к ZooKeeper: выбор лидера через эфемерный узел, чекпоинты, счётчик эпох. Лидер приостанавливался посреди расчёта на 40 секунд, запасной координатор доделал расчёт с чекпоинта. Опыт проведён без защиты и с защитой по эпохе (FENCING=1).

## Структура

- `compose.yaml` — три сервера ZooKeeper в Docker
- `config/` — zoo.cfg каждого из серверов
- `coordinator/coordinator.py` — координатор расчёта
- `coordinator/Dockerfile` — образ координатора
- `stage.ps1` — сценарий опыта (запуск двух координаторов, приостановка лидера, сбор журналов)
- `logs/` — журналы всех запусков координаторов
- `outputs/` — выводы команд текстом
- `otchet_dz4.docx` — отчёт

## Запуск

Нужны Docker Desktop, запущенный RustFS (S3 на порту 9100) с бакетом hh-lake из ДЗ № 3.

```
docker compose up -d
cd coordinator
docker build -t zkcoord .
cd ..
powershell -ExecutionPolicy Bypass -File stage.ps1 -Fencing 0 -Run nofence
powershell -ExecutionPolicy Bypass -File stage.ps1 -Fencing 1 -Run fence
```
